Pipeline reference

Nine steps through the guardrail pipeline

From voice input to cited response, the pipeline executes nine steps in sequence. The simulator above traces each step with timing.

01
Technician speaks

One-handed. One button. Web Speech API captures audio from the device microphone, no install required.

Channel: Browser mic
02
G1 normalises

Raw transcription is cleaned and reformulated into a structured query by the LLM with a strict system prompt.

< 0.8s
03
G2 checks scope

Top-1 similarity pre-check against the corpus. If nothing is remotely relevant, refuse immediately before spending retrieval budget.

< 0.3s
04
ChromaDB retrieves

Top-3 chunks by cosine similarity. nomic-embed-text embeds the query. Procedural sections returned with metadata.

< 1.2s
05
G3 validates confidence

Best chunk similarity must be ≥ 0.70. Below threshold: refuse with explanation. Never generate from partial context.

< 0.1s
06
G4 flags safety

Scans retrieved chunks for LOTO, lockout, high voltage, pressure vessel, hazmat keywords. Mandatory safety prefix if triggered.

< 0.2s
07
Llama 3.2 generates

Structured prompt enforces step-by-step format, maximum 5 steps, citation required. Response generated entirely locally.

< 4.5s
08
G5 enforces citation

Validates source reference is present in output. If missing, one retry. If still absent, response is blocked.

< 0.2s
09
Answer delivered

Cited, structured procedure appears on the technician's phone. Section number, page range, document title. Traceable to source.

Total: < 8s (target)
